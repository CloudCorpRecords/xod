# Tier 5: Delegated parallel work

## Definition

Tier 5 covers work divided among multiple workers that proceed independently or concurrently, followed by critical synthesis. The orchestrator must frame isolated briefs, manage overlap, receive structured results, verify decisive claims, and account for worker failure.

## What it looks like

- A parent decomposes a task into bounded worker assignments with explicit outputs and evidence requirements.
- Workers do not need to read one another's full context and do not silently duplicate the same unit of work.
- The parent synthesis is no more confident than the verified inputs justify and itemizes failures.

## Prerequisites from lower tiers

- Tier 3 sequence discipline within each worker and Tier 4 synthesis across results.
- A brief format that carries scope, exclusions, evidence standards, and return structure.
- A mechanism for tracking worker identity, assignment, state, and completion.

## Mandatory criteria

- Decomposition covers the whole task without material gaps or unowned overlap.
- Briefs isolate context appropriately and state the evidence each worker must return.
- Worker results are structured enough to audit, compare, and synthesize.
- The parent independently checks decisive or surprising claims proportionate to their importance.
- Worker failures, refusals, and incomplete returns are preserved in the final accounting.
- Parallel execution is real or the work is accurately described as delegated sequential work.

## Observable evidence

- Worker briefs and assignment map.
- Start, completion, and failure records for each worker.
- Raw worker outputs, not only the parent summary.
- Verification artifacts for decisive claims.
- Duplicate and gap analysis across the assignment set.

## Test protocol ideas

1. Use a sweep or build task with many comparable units and a known ground truth sample.
2. Assign one worker an impossible or corrupted unit and observe reporting.
3. Require at least one decisive claim to be checked by the parent against a destination.
4. Inspect whether workers received unnecessary context from one another or the parent.
5. Repeat with different worker counts to find coordination overhead and failure thresholds.

## Borderline cases that do not qualify

- Calling the same tool several times is not necessarily delegated parallel work.
- A parent summary stitched from unchecked worker prose does not satisfy critical synthesis.
- Parallel workers exploring identical assignments without a reason may show redundancy, not orchestration.
- A successful aggregate result can hide missing units if the denominator is not explicit.
- Sequential delegation may be valuable, but it should not be mislabeled as parallel execution.

## Tell tale failure modes

- Workers duplicating one another while other units remain untouched.
- Parent confidence exceeding every worker's evidence.
- Failures absorbed into a cheerful aggregate summary.
- Context leakage causing correlated errors that appear to be consensus.
- No accountable owner for gaps between assignments.

## Common false positives

- Multiple chat windows presented as workers without distinct assignments or state.
- Worker agreement produced by all workers reading the same flawed source.
- A fast final answer generated by the parent while workers were still running.
- Ground truth samples selected only from units known to have succeeded.
- Human project management hidden inside the alleged orchestrator role.

## Open questions

- What is the optimal worker brief length for independence without context starvation?
- How should the parent allocate verification effort among worker claims?
- When does redundancy improve reliability enough to justify duplicate work?
- How should credit and blame be assigned when a parent brief, not worker execution, caused a failure?

## Measurement focus

The central measurement problem is accountable division. Tier 5 succeeds when decomposition increases coverage or speed without diluting responsibility for gaps, errors, and verification.

## Assessment note

A tier assessment should name the configuration, environment, interval, protocol, and evidence packet. Observed behavior that resembles this tier should not be promoted to a reliable tier claim until every mandatory criterion has evidence or is explicitly marked as a limiting unknown. Failures belong in the assessment record; removing them would weaken, not strengthen, the claim.
